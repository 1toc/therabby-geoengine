# Pixel Explorer v0.1 — PLATEAU実在都市×ピクセルアート×徒歩/運転

## 試す方法
ローカルに駅東口LOD2/道路/地形の生成済みデータを持つGeoEngine作業フォルダで、変更ブランチを取得して次を実行。

```powershell
python -m http.server 8767 --bind 127.0.0.1
```

ブラウザで [駅東口 Pixel Explorer](http://127.0.0.1:8767/viewer/citywide-v1.html?station_lod2=1&pixel=1) を開く。

- 「高密度ピクセルアート」：ON/OFFで通常写真と比較
- 「アイソメ俯瞰」：平行投影の斜め俯瞰。スライダーで表示幅を調整
- 「通常視点」：既存のカメラへ戻る
- 「駅前を歩く」：既存の衝突判定付き徒歩。W/A/S/Dで移動、マウスで視線
- 「車を運転する」：読み込んだOSM道路近くで起動し、W/S加減速、A/D操舵、Spaceブレーキ。Escで終了
- 「ドットの大きさ」：2/3/4px。2pxが高密度表示

## 処理構造
1. PLATEAUのLOD1/LOD2形状と公式JPEGのUVを保持。元の都市データ、GLBは変更しない。
2. LOD2写真を建物単位で最大512pxへ縮小・減色・輪郭の局所強調。オリジナル写真へ戻せる。これは独立したイラスト制作ではなく**自動処理の試作**。
3. WebGLRenderTarget低解像度レンダリング+最近傍拡大。色の段階化と簡易エッジ強調をシェーダーで適用。
4. 平行投影カメラは原点（EPSG:6677）を変更しない。元の視点・タイル選択コードは利用継続。
5. 自動車はOSM道路中心線から最短点を求め、推定幅の範囲内で加減速と操舵を許す。車線・進路・交通規則は再現しない。

## 必ず守る前提
- 本GitHubリポジトリはソース・手順のみ。PLATEAU/DEM/OSM由来の実データ、写真タイルは再配布条件を確認するまで同梱しない。
- 平行投影の俯瞰と運転席視点の両方を厳密な「アイソメトリック」にすることはできない。運転は追従カメラを採用。
- 写真からの減色だけでは『Whisper of the House』級のアーティスト制作の画風には達しない。3棟を手作業で確認・修正する次段階が必要。
- 運転は**見た目と入力の試験**。OSMの推定幅と高さを走行制約に使っており、停止線、信号、交差点構造、車線、車両力学、建物との車体衝突、合法走行の判断は未対応。
- 医療・運転再開評価に使用しない。道路と建物の現況差・データ整備状況を説明し、臨床シミュレーターへの組込前に精度検証する。
- 描画モードの性能はIntel UHD Graphics 770実機で未計測。計測時の通常ベンチマークは既存条件を保持するためピクセル処理をバイパスする。

## 検証項目
- `node --test tests/pixel-explorer-core.test.mjs`
- `node --check viewer/geoengine-pixel-explorer.js`
- `node --check viewer/citywide-v1.js`
- PLATEAU写真ON/OFFで、形状・UV・建物位置が変化しない
- Pixel ON/OFF後、公式写真に戻る
- アイソメ切替後、徒歩モードを開始/終了できる
- 運転時に、推定道路外では停止する。Escで終了できる
- 俯瞰/地上/道路追従/10分測定が従来どおり利用できる
- 1280×720、内蔵GPUで、写真メモリ/平均FPS/p95を従来モードと比較する
